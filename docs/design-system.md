# Constella 界面设计规范

> 适用于 `apps/web`。风格参照 Claude Code 桌面版和 CC Switch：**紧凑、安静、内容优先**。配色和字体走主题变量，用户能在「设置 → 外观」里自己换，所以规范只管布局、尺寸和组件，不写死颜色。

## 1. 原则

1. **紧凑**：信息密度高于装饰。正文 14px，控件高 32px，卡片内边距 12–14px。手机上也不放大。
2. **安静**：大面积是中性色。主色只给「当前选中」「主操作」「数据」三类东西，一屏里不超过两三处。
3. **线条代替色块**：用 1px 细边框和分隔线划分区域，少用底色块和阴影。只有浮层（弹出面板、对话框、提示）才带阴影。
4. **过程折叠，结果展开**：工具调用、思考过程默认收成一行灰字；回复正文、关键数字直接展示。
5. **一处一种做法**：同一种东西全站长得一样，统一用 `components/ui.tsx` 和本文的配方，不在页面里重新发明。
6. **数据尽量给全**：在合理的前提下，用户能看到的数据越多越好。默认视图保持安静（一行摘要），多出来的数据放进点开后的下一层（`Sheet` 详情面板），而不是堆在列表里，也不是干脆不给。详情里给全系统记下的东西：精确时间、执行者、来源设备和 IP、涉及的对象（ID 换成名字，命令给原文）、改动的前后值，最后留一个折叠的「原始记录」。"合理"的边界有三条：
   - 密钥、令牌、密码不显示也不记录明文，只记「已设置 / 已清除」；
   - 很长的文本在记录时截断，在界面里可展开，不撑破布局；
   - 记不下来的数据补记在写入处：对象以后可能被删除、ID 查不回来，所以审计记录要同时存名字和改前改后的值，而不是只存 ID。

## 2. 主题变量（不要写死颜色）

颜色全部来自 `src/index.css` 里的变量，由 `<html>` 上的属性切换（`lib/appearance.ts`）：

| 属性 | 取值 | 说明 |
|---|---|---|
| `data-mode` | `light` / `dark` | 已解析的明暗（「跟随系统」在 JS 里处理） |
| `data-palette` | `nebula`（默认，紫粉）/ `clay`（陶土）/ `ocean`（海洋） | 配色 |
| `data-font` | `sans`（默认）/ `serif` | 标题和回复正文的字体 |
| `data-emoji` | `flat`（默认，Twemoji）/ `mono`（Noto Emoji 单色）/ `system` | 表情符号字形；字体只覆盖表情码位，排在每个字体栈最前（`--font-emoji`），数字、©、箭头、✓ 仍用正文字体 |

| 变量 / 工具类 | 用途 |
|---|---|
| `--bg` / `bg-app` | 页面底色 |
| `--sidebar` / `bg-sidebar` | 侧边栏、手机底部导航 |
| `--surface` / `bg-surface` | 卡片、输入框、浮层 |
| `--surface-2` / `bg-surface-2` | 悬停、用户消息气泡、代码块、分段控件底 |
| `--border` / `border-line` | 所有边框和分隔线 |
| `--text`，`--muted` / `text-muted` | 主文字、次要文字 |
| `--color-accent` / `bg-accent`、`text-accent` | 主色：选中、链接、数据 |
| `bg-accent-grad` | 主色渐变（主色 → `--accent-2`）：只用于 `Button variant="primary"`；开关、发送按钮用纯色 `bg-accent` |
| `--color-accent-soft` / `bg-accent-soft` | 主色淡底：图标底、徽标 |
| `--ok` / `--warn` / `--danger` | 状态色，只表示状态，不拿来区分数据系列 |
| `--series-1`…`--series-6` | 图表分类色，固定顺序（蓝、橙、青、黄、粉、绿），明暗各一套，已用 dataviz 校验脚本验证 |

- 选中态、悬停态用文字色混透明：`bg-[color-mix(in_oklab,var(--text)_9%,transparent)]`（选中），`_5%`（悬停）。这样三套配色、明暗都自动成立。
- 新增配色：在 `index.css` 里加 `:root[data-palette="x"]` 和 `:root[data-palette="x"][data-mode="dark"]` 两段，覆盖上表的变量，再在设置页的 `PALETTES` 里登记。
- 例外：远程桌面查看页固定深色背景（`#0b0d18`），因为画面本身是桌面截图；设置页的配色预览色块写死各配色的主色。
- **滚动条**：全局细滚动条（8px，透明轨道，圆角拇指，用文字色 18%，悬停加深），在 `index.css` 统一设置，页面里不要单独改。

## 3. 字体与字号

- 字体：`font-sans`（界面）、`font-display`（页面标题、空状态标题、agent 回复正文，跟随外观设置）、`font-mono`（命令、模型名、ID、代码）。
- 数字一律加 `tabular-nums`。

| 层级 | 字号 / 字重 | 用在 |
|---|---|---|
| 大数字 | `font-display text-2xl font-medium` | 统计卡片、回顾页指标 |
| 页面主标题 | `font-display text-xl font-semibold` | 回顾页标题这类内容型标题 |
| 顶栏标题 | `font-display text-[15px] font-semibold` | `Header` |
| 对话正文 | `text-sm`（14px），`.prose-chat` 行高 1.65 | 用户消息、agent 回复、输入框、过程行 |
| 正文 / 控件 | `14px`（body 默认）、`text-[13.5px]` | 列表、按钮、输入框、侧边栏 |
| 辅助 | `text-[13px]`、`text-xs` | 字段标签、分组标题、说明 |
| 最小 | `text-[11px]`–`text-[11.5px]` | 坐标轴、用量行、时间戳、徽标 |

不用 16px 以上的正文，不用全大写的英文标签。

## 4. 尺寸、间距、圆角

- **高度**：顶栏 48px（`h-12`）；按钮、输入框、下拉框、菜单项 32px（`h-8`）；侧边栏条目、设置导航项、侧边栏搜索框、分组标题、工具栏和浮层触发器、小按钮 28px（`h-7`）；分段控件容器 28px、选项 24px；chip 和行内小按钮 20–24px。
- **图标**：lucide，`strokeWidth={1.8}`。条目、顶栏、关闭按钮、`IconButton` 里都是 16px（`size-4`），密集行内 14px（`size-3.5`），空状态 24px；不用 `size-5` 及以上（手机底部标签除外）。
- **间距**：页面左右 `px-4`；区块之间 `space-y-5`；区块标题和内容 `space-y-1.5`；卡片内 `p-3`–`p-3.5`；列表行 `px-3.5 py-2.5`。
- **圆角**：照 Claude Code 收得很小，档位在 `index.css` 的 `@theme` 里统一调小了：`rounded`（3px）用于徽标，`rounded-md`（4px）用于按钮和条目，`rounded-lg`（6px）用于气泡和代码块，`rounded-xl`（8px）用于卡片、输入框、浮层，`rounded-2xl`（10px）用于对话框；状态点和头像用 `rounded-full`。不要绕过档位写任意值（比如 `rounded-[12px]`）。
- **宽度**：桌面侧边栏 256px（`w-64`），主内容 `max-w-4xl`，对话和表单 `max-w-3xl`。

## 5. 布局

- **桌面（≥ lg）**：固定左侧边栏，从上到下依次是：
  - 搜索框
  - 主导航（新建 agent、首页、桌面、任务、学习、成果、审计、用量、性能、回顾）；「审计」有待处理事项时右侧显示 warn 色数字
  - 按 agent 分组的对话列表（组名旁有「+ 新对话」「设置」两个按钮）
  - 账户行（头像首字、名字、设置齿轮）
- **手机**：底部五个标签（首页、桌面、任务、学习、设置），高度尽量小；只在桌面侧边栏出现的页面（成果、审计、用量、性能、回顾），在设置页顶部放入口行（`lg:hidden`）。
- 顶栏：标题在左，操作在右；桌面上对话页不显示返回按钮（`backMobileOnly`）。
- 浮层：小选择用 `Popover`（在触发按钮上方弹出，点外面或按 Esc 关闭）；表单、确认、长内容用 `Sheet`（手机从底部弹出，桌面居中）。

## 6. 组件配方

全部在 `src/components/ui.tsx`，优先复用。

| 组件 | 要点 |
|---|---|
| `Button` | `primary`（渐变主色）、`secondary`（白底细边框）、`soft`（`bg-surface-2` 无边框：设置行、浮层、卡片里的次要操作）、`ghost`、`danger`；尺寸 `sm` 28px / `md` 32px / `lg` 40px（`lg` 只给手机底部主操作） |
| `inputClass` / `selectClass` | 白底细边框、`rounded-lg`，悬停加深边框，聚焦主色边框，`text-[13.5px]` / `text-[13px]` |
| `Toggle` | 36×20，打开时纯色 `bg-accent` |
| `Segmented` | 指标切换、二三选一：容器 `h-7 p-0.5 bg-surface-2`，选项 `h-6`，选中项 `bg-surface border border-line`，不加阴影 |
| `Card` | `rounded-xl border bg-surface`，可点击时悬停加深边框 |
| `Section` | 标题 `text-xs font-medium text-muted`，右侧文字操作用 `text-xs text-muted hover:text-[var(--text)]`，不用主色 |
| `Row` | 可点击的列表行：图标、标题和副标题、右侧内容；在 `Card` 里用 `divide-y` 分隔。设置项不用它，用 `SettingRow` |
| `SettingGroup` / `SettingRow` | 设置页：组标题 `text-sm font-semibold`，组间 `space-y-5`；行 `py-2.5`，左边标题 `text-[13.5px] font-medium` + 描述 `text-xs text-muted leading-snug`（可换行，写短），右边控件；行间 `divide-y`，不套卡片、不放图标；控件宽的行加 `wide`，窄屏时换到下一行；长列表里每行只有名字和几个按钮的（模型、provider、设备、容器、操作记录）加 `dense`，`py-1.5` |
| `navItemClass(active)` | 侧边栏和设置导航的条目：选中是文字色 9% 的中性底，悬停 5%；不要再手写这串 color-mix |
| `Tabs` | 下划线标签：同一份数据的不同视角；选中项加粗加 2px 主色下划线，右侧可放一句 muted 说明 |
| `StatTile` | 统计卡片：上面是 `text-xs text-muted` 标签，下面是数字（`lg` 是 `text-2xl`，`sm` 是 `text-base`），`tabular-nums` |
| `Badge` | `rounded px-1.5 text-[11.5px]`，tone 只用 muted / ok / warn / danger / accent |
| 状态点 | 8px 圆点：空闲是空心描边，进行中是主色并闪烁，等审批是 warn，失败是 danger |
| `Popover` | 浮层：触发器默认 `h-7 px-1.5 text-[13px] text-muted`，展开时 `bg-surface-2`；面板 `rounded-xl border bg-surface shadow-xl`，`side` 定上下、`align` 定左右。面板内 `p-3`，分节线左右内缩（不通栏），每行左标签、右 `text-muted tabular-nums` 数值；进度条 `h-1.5 rounded-full`，轨道用文字色 12% |
| `MenuItem` / `MenuDivider` | 菜单（如账户菜单）：面板 `w-60 p-1.5`，首行可放 `text-xs text-muted` 的身份信息；项 `h-8 px-2.5 gap-2.5 rounded-md`，16px muted 图标，右侧提示用 `text-xs text-muted`（快捷键、›、↗）；用分隔线分组，退出登录放最后一组。红色只给删除数据的操作 |

## 7. 对话

- **新对话**：问候和输入框居中放在一起，像 Claude 首页：「{agent 表情} 早上好 / 中午好 / 下午好 / 晚上好 / 夜深了，{名字}」（`font-display`，约 30px），输入框提示语「今天想让{agent}做点什么？」。不放示例、不写「派活」这类说法。
- **一轮一块**：用户的一条消息加上 agent 为它做的所有事是一轮（`RunView`，`<article>`）。轮与轮之间 32px（`space-y-8`），轮内各块之间 12px（`space-y-3`），靠间距而不是分隔线看出边界。一轮从上到下：用户消息 → 回复正文和过程行交替 → 结束状态 → 用量行。
- **用户消息**：靠右，`bg-surface-2 rounded-xl px-3 py-2 text-sm`；时间放在气泡左边、底部对齐（`text-[11px] text-muted`），不单独占一行。任务进行中追加的指示也是气泡，左边标「追加指示」。带附件的消息，附件放在气泡上方右对齐：一张图片按原比例显示（`max-h-60`），多张图片是 96px 方块缩略图，点开全屏看（`Lightbox`，Esc 或点任意处关闭）；其他文件是 40px 高的下载卡片（文件图标 + 名字）。只发附件没写字时不显示空气泡。
- **agent 回复**：无气泡，`font-display text-sm`，Markdown 排版（`.prose-chat`）。流式输出不另加闪烁圆点，进行中由下面的状态行表示。
- **交互界面**（智能界面，在「设置 → 回答」里可关）：回复正文里的 ` ```ui 标题 ` 块是一段组件程序，在正文里原位用原生组件渲染，**不套外框、不加标题栏**，像 ChatGPT 一样是回答的一部分；块与块、块与文字之间 16px。组件库在 `components/genui/components.tsx`，全部照本规范：卡片 `rounded-xl border bg-surface p-3.5`，统计卡同 `StatTile` 的层级（`text-xs` 标签 + 22px 数字），分段选择同 `Segmented`，滑块是 4px 轨道、主色填充到当前值、16px 白底主色描边的圆钮（`.genui-range`），框图节点用 `bg-surface-2` 底、居中图标与标题、节点之间 14px 箭头，图标列表是 32px 淡色图标块 + 粗体标题 + muted 说明，图表是 SVG（虚线网格、圆角柱、`--series-*` 配色、悬停浮层，选中/高亮之外的柱子降到 45%）。生成过程中从写好的部分开始逐步显示（流式），还没有内容时一行「正在生成界面…」。桌面悬停时右上角浮出小工具条（看源码、全屏、更多：重新运行、复制源码），触屏不显示。出错时块下面一行 danger 状态行「界面出错：…」+「重试」+「让 agent 修复」；只有一部分写错时其余照常显示，块下一行 `text-xs text-muted`（warn 色图标）「界面有一部分写错了，已跳过：…」。属性或组件不对时照常显示，工具条的「看源码」带一个 6px warn 色圆点，源码视图顶部列出诊断。回答在块写完之前中断时，显示已生成的部分，下面一行「回答中断了，界面只显示了已生成的部分」+「让 agent 补全」。远离视口、还没运行过的块是一个 96px 的 `bg-surface-2` 淡底占位（不写「正在生成」）；运行过的块显示上次的样子，靠近视口时再接管交互。界面里的发送（按钮的 `send`、`Choice` 的提交、`Suggestions`、测验的「讲解错题」）走和输入框同一条路径（任务进行中自动变成追加指示）。` ```ui-html ` 是自包含网页的退路：沙盒 iframe、细边框圆角、高度自适应。
- **不是用户打的轮次**：hub 中断后自动接着做的那一轮、空着发送的「继续」、从诊断报告里采用方案后的那一轮、监督员把没做完就停下的 agent 拉回来的那一轮，不显示成气泡，显示成居中的分隔线标签「—— ↻ 中断后自动继续 · 时间 ——」/「—— ↻ 继续中断的任务 · 时间 ——」/「—— ✓ 采用方案「标题」 · 时间 ——」/「—— 👁 监督员让它接着做 · 时间 ——」；采用方案和监督员拉回的下面再加最多三行居中灰字，是发给 agent 的指示。
- **迟到的回答**：agent 不再等之后主人才回答的问题，作为用户气泡显示回答，左边的时间位置写「回答「问题前 14 字」 · 时间」。
- **过程行**：连续的工具调用、思考、桌面操作和已处理的审批收成一行：14px 图标（只有思考是脑图标，以命令为主是终端，以改文件为主是文件，其余是扳手）+ `text-[13px] text-muted`，例如「运行了 2 条命令，调用了 1 个工具 · 1 项审批已批准 ›」，有失败时后面跟「· 1 个失败」（danger）。窄屏时概要截断，失败数和箭头不截。点开后左侧一条竖线（`border-l`，对齐图标中线），每步一行等宽字（审批步骤显示完整命令和结果）；再点单步看输入输出。进行中这一行图标换成转圈、文字换成当前命令；任务已结束但没跑完的步骤不转圈，显示「未完成」图标。
- **状态行**：进行中 / 等待审批 / 失败 / 已停止，和过程行同一套 13px + 14px 图标的格式，单独一行。失败用 danger 文字和 ⊗ 图标，**不加底色块**。
- **系统处理行**：hub 自己做的事（自动修复 runner 和实例用扳手图标、监督员介入和维修员用眼睛图标、诊断报告用听诊器图标；报告卡片上 panic 用警报器、实例故障用显示器、求助用救生圈）也用状态行的格式，单独一行，不折叠也不做成卡片；关联了诊断报告的行可点，跳到 `/audit?id=…`，行尾带报告的状态徽标。
- **需要主人的卡片**只有三种，都不折叠，边框用 warn 色混 45%，只在待处理时出现：
  - **审批卡片**：批准 / 拒绝两个按钮；处理后并进旁边的过程行，自动批准的显示为「已自动批准」。
  - **选择卡片**（agent 调用 ask_user）：问题正文，下面每个选项一行（整行可点，`rounded-lg border px-3 py-2`，标题 13.5px 加粗，说明 `text-xs text-muted`），推荐项边框用主色混 45% 并带「推荐」徽标；最后一行是「或者直接写你的回答」输入框（右侧 24px 发送按钮）和一个文字按钮「不选了，让它自己判断」。回答后收成一行灰字「问「…」→「回答」」。agent 在等回答时，输入框提示语换成「直接写下你的回答…」，发出去的文字就是回答。
  - **诊断报告卡片**（`IncidentCard`）：标题行（图标、标题、时间、状态徽标）；原因 13px；系统已经做过的处理用 ✓ 小字列出；错误信息默认收起；方案每个一行，右侧「采用」按钮（推荐项用 primary，其余 secondary，`sm`）；底部「忽略」文字按钮。分析中显示转圈和「诊断员正在分析原因，稍等…」。处理完的只在第一次提到它的位置显示成一行系统处理行加状态徽标。
  - 选择回答后不并进过程行，收成一条状态行「问「…」→「回答」」，因为回答本身是主人的决定。
- **成果卡片**（agent 用 send_file / artifact_save / artifact_edit 交付的文件和文档）：是结果，不折叠，出现在交付它的位置，成功的那次工具调用不再单独占一行过程行。卡片 `max-w-md rounded-xl border px-2.5 py-2`：左边 36px 图标块（`bg-surface-2 rounded-lg`，图标按类型），中间标题 13.5px 加粗 + 一行 `text-xs text-muted`「类型 · 大小 · 第 N 版（只在多于一版时）· 这一版的说明」，右边下载按钮。图片在卡片上方多一张缩略图（`max-h-72`）。点卡片打开它交付时的那一版；正在预览的卡片边框用主色混 45%。
- **实例页的卡片 / 列表**（`/instances`）：标题栏右侧是图标 `Segmented`（卡片 / 列表，带 `title`），选择记在本机（`appearance.instanceView`）。卡片是缩略图在上、信息在下；列表是一张 `divide-y` 的卡，一行一个实例：80–96px 缩略图、类型图标（窄屏隐藏）、名字和概要、状态徽标。
- **实例小窗**（`InstanceWindow`）：在对话里看 agent 操作实例不用离开对话。对话顶栏的显示器按钮（agent 正在用时带主色闪烁点）、过程行里的实例操作、接管请求卡片的「先看看」都打开它。全站只有一个，切页面和刷新都保留，在这个实例自己的页面上隐藏。`rounded-xl border bg-surface shadow-xl`，`z-40`（在 Sheet、审批浮窗、提示之下）；32px 标题栏：类型图标、名字、muted 状态，右边 24px 按钮：系统小窗（浏览器画中画，切走标签页也能看，支持时才有）、接管、打开实例页、关闭。只看不操作，标题栏和画面都可拖动，双击打开实例页；缩放角在朝向屏幕中间的那个角，位置和大小记在本机。
- 不在这个对话页时，待审批和选择会以浮窗出现（桌面右下角、手机顶部），可直接处理，也可以先关掉；有待处理时页面标题前加「(N) 待处理」。首页把未处理的诊断报告放在「需要你处理」分组，最多三张，右侧链接到审计页。
- **用量行**：一轮的最后一行，`text-[11px] text-muted tabular-nums`，用 `·` 分隔：模型 · 上下文 · 输入（缓存）· 输出 · tok/s · 耗时；外观设置里可关。右侧 👍👎 是 24px 按钮、14px 图标：有鼠标的设备上悬停这一轮才出现，触屏上常显，评过的一直显示。
- **输入区**：`rounded-2xl` 框里放输入框（14px）和右下角发送按钮（28px `rounded-lg`：有内容时 `bg-accent`，空着时 `bg-surface-2 text-muted`，发送中转圈；任务进行中且输入为空时换成深色停止按钮）。上一轮任务异常中断时，发送按钮保持可点，空着发送就是「继续」，提示语也要说明这一点。框下面一行工具栏：左边「+」附件，右边依次是上下文进度环、模型、推理强度。Enter 发送，Ctrl/⌘/Shift+Enter 换行，输入法选词时不发送，触屏键盘上 Enter 换行。附件可以点「+」选、直接粘贴（截图、复制的图片或文件）、或拖进输入框（拖入时边框变主色）；Office / 网页选区粘贴时按文字处理。待发的附件在输入框顶部一排 56px 方块：图片是本地缩略图（上传中盖一层转圈），其他文件是 176px 宽的卡片（名字 + 扩展名，上传中写「上传中…」）；右上角 20px 圆形移除按钮，有鼠标时悬停才出现。上传完之前不能发送；只有附件也可以发送。

## 8. 成果

- **预览面板**：URL 里带 `?artifact=…&av=版本` 就在当前页打开，所以任何页面都能打开、手机上返回键能关、链接能直接分享。桌面上是右侧面板（`min(50vw, 760px)`，左边框，`bg-surface`），页面内容通过 `--panel-w` 让出位置，不遮挡；手机上全屏，左上角返回。
- 面板第一行：类型图标、标题（`font-display text-[15px]`）、下载、更多（复制内容、编辑、恢复此版本、重命名、前往对话、在新标签页打开；删除放最后一组，红色）、关闭。第二行（`border-b`）：「预览 / 源码」分段（文档、网页、SVG、表格才有）、版本下拉（每版一行：第 N 版、最新徽标、时间，下面一行是谁改的和说明）、右侧灰字「agent · 类型 · 大小 · 时间」、可编辑时一个 `soft` 的「编辑」按钮。
- 看旧版本时，第二行下面多一条 warn 色混 8% 的提示条「正在看第 N 版，最新是第 M 版。这一版：说明」，右边「看最新」文字按钮和「恢复此版本」按钮。恢复和主人编辑都会生成新版本，从不覆盖旧版本。
- 内容：文档用 `.prose-chat` 排版；网页放在 `sandbox="allow-scripts …"`（不给 allow-same-origin）的 iframe 里，白底；表格用紧凑表（表头吸顶，`text-[12.5px] tabular-nums`，最多 1000 行）；代码和源码 `font-mono text-[12.5px] leading-5`；图片、SVG、视频居中放在文字色 4% 的底上；PDF 桌面内嵌，手机给「打开 PDF」按钮；其他文件显示空状态加下载按钮。
- 编辑：正文换成等宽字 textarea，第二行换成「改了什么（可选）」输入框 +「取消」+「保存」（primary），有未保存修改时关闭要确认。
- **成果页** `/artifacts`：一行筛选（搜索框、类型下拉、agent 下拉，条件存在 URL 里），下面是 `Card` + `divide-y` 的列表行（32px 图标块、标题、「agent · 类型 · 大小 · 第 N 版 · 时间」），底部「共 N 个」。agent 详情页有「成果」标签，对话顶栏有成果数量按钮（没有成果时不显示），点开是这个对话的成果列表。
- 文件下载、内嵌一律走 `/api/artifacts/:id/file`：只有图片、PDF、音视频按原类型内嵌，文本（包括 HTML）按纯文本，其余只能下载，全部带 `nosniff` 和 CSP sandbox，交付的文件永远不能以主人的登录身份在本站运行。

## 9. 审计页

- `/audit`：顶部 `Tabs` 三个视图——「待处理 N」（未处理的报告，用完整的 `IncidentCard`）、「全部记录」（紧凑行：图标、标题、agent · 类型 · 时间、右侧状态徽标，点开用 `Sheet` 显示报告）、「操作日志」（时间 `w-24 text-xs tabular-nums`、动作中文名、执行者小字，下一行 `text-xs text-muted` 摘要；没登记中文名的动作用等宽字原样显示）。
- **操作记录的详情**：「操作日志」每行、设置 → 安全里的「操作记录」每行（右侧 `›`）都可点，打开同一个 `AuditDetailSheet`（`components/AuditDetail.tsx`；动作名、字段名、取值的中文都在 `lib/audit.ts` 一处登记，两处列表共用）。从上到下：
  - 时间（精确到秒，后面跟「N 小时前」）、执行者（名字，下面一行等宽小字是原始 ID）、来源（设备 · IP）；
  - 「涉及」：agent、对话（可点）、任务原文和状态、审批的命令原文和结果、定时任务、桌面、诊断报告；对象已被删除就不显示这一块，名字用记录里存的；
  - 「变更」：每个改动的字段一行，`旧值 → 新值`（旧值 muted）；密钥只写「已设置新值（不记录内容）」；
  - 「详情」：以上没覆盖的其余字段；
  - 折叠的「原始记录 · #编号」：动作的原始名和格式化后的 JSON。
- 新增会写审计的操作时：把对象的名字和（改动类操作的）前后值一起记进 `detail`；来源设备和 IP 不用自己记，请求里写的审计会由 `audit()` 自动附上 `via`。
- 状态徽标：分析中 accent、待处理 warn、已自动处理 / 已采用方案 ok、已忽略 muted。

## 10. 数据展示（统计、用量类页面）

- **统计卡片**：一行 2–4 个，用 `StatTile`。小标签（`text-xs text-muted`）在上，数字（`text-2xl` 或次级 `text-base font-semibold`，`tabular-nums`）在下。主次两行时，次要指标卡片更矮。
- **筛选**：放在一行里，靠右；时间范围用下拉（`h-8`），维度用 `Segmented` 或图标分段。
- **表格**：
  - 表头 `text-xs text-muted font-medium`，行高约 44px，行之间 `border-b border-line`，不加竖线和斑马纹。
  - 模型名、ID 用 `font-mono text-[12.5px]`。
  - 数字 `tabular-nums`，单位用小一号的 muted 字（如 `100 <span class="text-muted text-xs">tok/s</span>`）。
  - 空值显示「—」。
  - 底部左边是「共 N 条记录」，右边是分页。
- **标签页**：下划线式文字标签（选中项文字加粗，下面一条 2px 主色线），用于同一份数据的不同视角（请求日志、模型、定价……）。
- **对象清单**（性能页的实例 / agent / 服务）：一行一个对象，用 `Card` + `divide-y`；左边 32px 图标块（有 emoji 就用 emoji）、名字和一行 `text-xs text-muted` 概要，右边两行数字（上行 CPU，下行内存）；点开就地展开容器明细，不跳页。整机 / 容器的区别、读不到的指标要在页面里写明，不留空白让人误以为是 0。

## 11. 图表

遵循 dataviz 规范，复用 `components/BarChart.tsx`：

- **时间序列**（性能页的 CPU / 内存 / 网络曲线）用 `components/LineChart.tsx`：横轴约 5 个刻度，纵轴 3 条网格线；单一序列用主色，网络上下行两个序列按 `--series-1` / `--series-2`，并在图表右上角的图例里直接标当前值；悬停显示十字线和各序列数值；同样带 `sr-only` 数据表（采样点多时按比例抽稀）。
- 图表内的轴文字和图表上方的当前值用 `text-[11px] text-muted tabular-nums`；纵轴刻度用短单位（`1.5GB`、`12%`），免得在手机上压到曲线。
- **单一序列用主色**，标题已经说明画的是什么，就不加图例。两个及以上序列才加图例，颜色按 `--series-1…6` 的固定顺序分配。浅色下青、黄、粉对比度略低于 3:1，所以每个分类都要在图例里直接标数值。
- 堆叠条（如上下文窗口构成）：段与段之间留 2px 间隙，剩余部分用中性轨道。估算出来的数字要注明是估算。
- 柱宽不超过 24px，顶端 4px 圆角、底部直角，从同一条基线长出来；折线 2px；数据点直径至少 8px。
- 网格线 1px 实线、`--border` 色，不用虚线；坐标轴文字 11px muted，刻度取整数或整十整百。
- 只用一条纵轴，不做双轴图。
- 默认带悬停提示：柱状图悬停显示单根柱的数值，折线图显示十字线加数值；附一份给读屏用的数据表（`sr-only`）。
- 文字永远用文字色，不用数据色。

## 12. 文案

- 简体中文，短句，直接说结果，例如「已保存」「今日预算已用完（$4.80 / $5）」。
- 按钮用动词：「生成总结」「发送测试」「查看全部」。
- 空状态：一句标题加一句下一步建议。
- 时间用相对时间（「刚刚」「3 小时前」），一周以上显示日期。
