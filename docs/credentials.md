# 凭据 / 隐私

Constella 可以连接 Bitwarden Password Manager，并由指定的审批 agent 审核其他 agent 的凭据访问申请。读取密码库里的条目；写入只有一种：主人在登录输入框里勾选「保存到密码库」时新增一个登录条目，不会修改或删除已有条目。Bitwarden Secrets Manager 是另一种产品，当前连接方式不适用其 access token。

## 连接密码库

在“凭据 / 隐私”中新增 Bitwarden 连接，选择美国区、欧洲区或填写自托管服务器地址，然后输入个人 API Key 的 client ID 和 client secret。这些信息由 hub 的 `SecretStore` 加密保存。每个连接使用独立的 Bitwarden CLI 数据目录。

登录之后还需要输入主密码解锁密码库。主密码只用于当次解锁，不持久保存；解锁会话仅存在 hub 内存。重启 hub 后需要重新解锁。锁定或断开连接会使该连接的访问授权失效。连接信息和主密码应通过管理页面提交，不要粘贴到 agent 对话中。

hub 运行环境需要 Bitwarden CLI；官方 hub 镜像包含固定版本。自行运行 hub 时，需保证运行进程可以调用 `bw`。API Key 登录成功并不代表密码库已经解锁。

## 第三方和自托管服务

除了官方美国区和欧洲区，也能连接 Bitwarden 兼容的第三方服务（例如 Vaultwarden）和自托管实例：服务器选「第三方 / 自托管」，填完整地址。内网地址（`localhost`、`10.x`、`192.168.x`、`172.16–31.x`、`100.64/10`、`*.local`）可以用 `http://`，其余地址必须用 `https://`，免得主密码和 API Key 走明文。

第三方服务用自签名证书或私有 CA 时，在同一个表单里展开「服务器证书」，把 PEM 证书贴进去。它只作用于这个连接，加密保存在 hub 里，调用 CLI 时写进该连接自己的目录并通过 `NODE_EXTRA_CA_CERTS` 交给它，不会放宽其他连接或 hub 本身的证书校验。

每个连接有独立的 CLI 数据目录和登录状态，同一个 hub 可以同时连官方区和多个第三方服务，互不影响。

## 申请和审批

1. 在管理页面指定审批 agent。
2. 业务 agent 查找条目摘要，提交所需条目、字段、使用目的和目标服务。
3. hub 为指定审批 agent 创建审核任务。审核上下文包含申请元数据，不包含密码和其他秘密字段值。
4. 审批 agent 批准或拒绝申请。hub 校验审批者身份及专用审核任务，业务 agent 不能自行批准自己的申请。
5. 批准后，只有原申请 agent 的原任务可以读取获准字段。授权最多有效 10 分钟，且只能消费一次。

普通操作的自动审批设置不会跳过凭据审批。审批 agent 不可用、审核失败或超时时不会自动放行。用户可在管理页面处理申请和撤销尚未使用的授权。

## 登录时自动填入

浏览器、Linux 桌面和安卓上要输入用户名、密码或一次性验证码时，agent 用 `credentials_fill`，不用自己向主人要，也不用你把密码发在聊天里：

1. 先看密码库：已解锁的连接里有这个网站（按域名匹配，子域名算同一个站）的条目，并且有需要的字段。
   - 指定了审批 agent：走上面的申请和审批流程，批准后由 hub 取出并直接填进页面；审批 agent 没批准或三分钟没回复时，才请主人输入。
   - 没有审批 agent：对话里的卡片给主人一个「使用密码库里的『某条目』」按钮，点一下即视为主人批准。
2. 密码库里没有（没连接、没解锁、没有这个站的条目），或者主人选择自己输入：对话页面弹出输入框，主人输入后提交。输入框里有「保存到密码库，下次自动使用」（默认勾选，有已解锁的密码库、且要的是用户名加密码时才出现）：勾选后 hub 把这个站的用户名和密码作为新条目写进所选密码库（条目名和网址都是域名；一次性验证码不保存），下次登录同一个站就走第 1 步。登录没成功也会存下，可以到 Bitwarden 里改或删。

值由 hub 直接填进页面，不会作为工具结果返回给 agent，不进模型上下文；输入的内容只在 hub 内存里交给正在等待的那次调用，不写数据库、事件、审计和聊天记录，调用后的页面内容里出现这些值时会被脱敏。审计里只有「谁为哪个站填了哪些字段、来自密码库还是主人输入」和「存进了哪个密码库」；写入时条目经 CLI 的标准输入传入，不出现在命令行参数里。

最多等 14 分钟。主人拒绝或没有及时提供时，输入框作废，agent 把能做的做完、说明在等什么凭据后正常结束这一轮：缺凭据而停下是在等主人，不算 panic，监督员也不会把它拉回来。主人让它继续时再弹一次输入框。

## 信息可见范围

连接列表、条目摘要、审批记录和访问记录不返回密码。审批记录保留对象引用、申请范围、用途、决定和时间等元数据。

**获准读取的字段会进入业务 agent 的模型上下文。** 模型提供方以及 agent 引擎自己的会话记录可能处理或保留这些字段。应用会对已知秘密在 hub 的事件展示和持久化路径中进行脱敏，但这不是针对整个运行环境的数据防泄漏保证，也无法阻止已获授权的 agent 复制或重新编码秘密。

锁定、断开和撤销只能阻止后续读取，无法收回已经交给 agent 的值。单次授权限制的是 hub 的读取次数，而非凭据在外部服务中的使用次数。应使用具备适当权限和有效期的专用服务凭据。

## 扩展其他服务

连接管理和权限审批依赖统一的 provider 接口。新增 provider 应实现连接状态、解锁/锁定、同步、条目摘要和指定字段读取，并复用 hub 的申请、审批和授权消费逻辑。provider 的错误信息必须转换为不含秘密的用户提示；不得直接记录外部 CLI 的输出、主密码或会话密钥。
